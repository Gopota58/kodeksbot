## 2026-09-17 — Аудит ВМ, харденинг демо, починка CI, деплой через git

### Контекст
Проверка «всё ли настроено и работает на ВМ в Yandex Cloud». Аудит (read-only): сервис работал,
но нашлись три реальные проблемы — публичный API-ключ из HTML открывал удаление корпуса,
не было rate limiting, диск занят на 84%. По «делай абсолютно всё, качественно» исправлено,
затем по «продолжай» — починен красный CI и ВМ приведена к репозиторию. Коммиты `14515ba … 8cdc376`.

### Сделано
**1–3. Харденинг демо.** Разделение ключей: `API_KEY` (публичный) → только `/ask`;
`ADMIN_API_KEY` → `/upload`, `/ingest`, `/documents`, `DELETE /documents/{file}`.
Админский в HTML не попадает: вводится кнопкой 🔑, живёт в `localStorage`, 401 его сбрасывает.
Rate limiting (`app.py`): скользящее окно 60 с на пару (IP, группа путей), `/ask` 30/мин,
админка 10/мин, 429 + `Retry-After`, считается **до** проверки ключа, `OPTIONS` не считается.
favicon: `static/favicon.svg` + маршрут `/favicon.ico` → редирект. Детали — `README.md`,
`docs/API.md`, `docs/DEPLOY.md`.

**4. ВМ:** swap 2 ГБ в `/etc/fstab` (`vm.swappiness=10`) — было 0 при 4 ГБ RAM;
`docker builder prune -f` освободил ~9.5 ГБ (**диск 84% → 52%**).

**5. Документация:** `README.md`, `docs/DEPLOY.md`, `docs/API.md`, `AGENTS.md`, `.env.example`
(последний был устаревший: обещал rubert-tiny2 и скачивание из HF — давно не так).

**6. Сверка ВМ ↔ репозиторий, найдено сверх плана:**
- `requirements.txt`: кириллица была **дважды перекодирована** (в git и на ВМ) — развёрнуто
  обратно; удалены 14 неиспользуемых пакетов (vosk, srt, pyinstaller*, kubernetes, PyPika…),
  шапка переписана.
- **`RERANK_MODEL` в `docker-compose.yml` репозитория НЕ БЫЛО ни в одном коммите** — жила только
  на ВМ. Добавлена в репозиторий (иначе `reset --hard` снял бы её → jina на 2 vCPU).
- Публичный ключ разъехался по 4 файлам (`config.py`, `.env.example`, `static/index.html`,
  `desktop_client.py`) → приведён к одному значению.
- `.workbuddy-ai/` не был в `.gitignore`/`.dockerignore` → добавлен в оба.
- Удалён отладочный мусор из корня (`_vmtest3.py` со старым ключом открытым текстом, логи).

**7. Мелочи:** `import fitz` → `import pymupdf as fitz` (снято deprecated-предупреждение);
дефолт reranker в `config.py` приведён к `all-MiniLM-L6-v2` (был jina — противоречило README,
AGENTS.md, ARCHITECTURE и .env.example); `.env.bak*` в `.gitignore` (внутри живые ключи).

**8. Починка CI (был красным с 2026-09-08, ни одного зелёного прогона).** Три независимые причины:
- `torch==2.14.0+cpu` **не существует на PyPI** (тег `+cpu` живёт только на
  `download.pytorch.org/whl/cpu`), в workflow не было `--extra-index-url` → падал шаг Install,
  Lint/Tests помечались `skipped`.
- Тесты требовали рабочий корпус `data/docs/`, а он в `.gitignore` → в CI его нет.
- `ask()` **маскировал** исходное исключение своим `ValueError("LLM вернул пустой ответ")`.

Лечение: `--extra-index-url` в workflow; `tests/conftest.py` сделан герметичным
(`EMBED_PROVIDER=hash`, временный `CHROMA_DIR`, `DOCS_DIR=tests/fixtures/docs/`, `RERANK_MODEL=""`,
`RAG_DISABLE_WATCHER=1` — поток watchfiles ронял процесс по SIGABRT уже после успеха,
фиксированные ключи); `ask()` пробрасывает исходную ошибку.

**9. Реальный баг, найденный тестом:** на пустом индексе `top_n = min(20, 0) = 0` → Chroma падала
с `TypeError: Number of requested results 0`. Добавлен guard `if n == 0: return []` + регрессионный
тест. Актуально для свежего деплоя без индексации.

**10. Тесты и линт:** `test_api.py` переписан под разделение ключей и лимиты; `ruff check .` доведён
до нуля и переведён в **обязательный гейт**. Побочно: публичный `/ask` больше не отдаёт наружу
`str(e)` (утечка путей) — общее сообщение клиенту + `log.exception`.

**11. Деплой:** ВМ отставала на 20+ коммитов (деплой шёл через `scp` мимо git) → приведена
к `origin/main`; процедура «scp + md5» в `AGENTS.md` заменена на git. Перед сбросом: бэкап `.env`,
тег `pre-1f097c2`, удалён `_vmtest3.py`. Образ пересобран (~20 мин), контейнер пересоздан.

- **Диск ВМ:** 76% → **60%** (12 ГБ свободно); удалены оба откатных образа, остался `latest`.

### Грабли
- **Публичный ключ в `static/index.html` — по определению не секрет** (view-source). Защита
  держится на rate limiting и на разделении ключей, а не на «секретности» публичного ключа.
- **Деплой только через git.** `scp` копит незаметное расхождение: сервис работает, а версия
  на сервере — двадцатидневной давности. Подробнее: `AGENTS.md` §4, concept
  `[[wiki/concepts/remote-deploy-git-not-scp]]`, скилл `remote-deploy`.
- **`docker builder prune -f`** удаляет только неиспользуемый кэш; `-a` снёс бы весь, и следующая
  сборка тянула бы `pip install` заново (torch — минуты).
- **Правка даже комментария в `requirements.txt` = пересборка ~20 мин** (слой `COPY requirements.txt`
  входит в кэш-ключ `RUN pip install`).
- Зависшее имя контейнера, обрыв долгих ssh на 120 с, `pgrep -f buildkit` — см. `AGENTS.md` §4.

CI зелёный (был красным с 2026-09-08), тесты герметичны (20 passed), `ruff` чистый.
Демо защищено разделением ключей и rate limiting. Диск ВМ 60%.
